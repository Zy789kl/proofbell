# 样例复核

下表是可复跑的构造案例。用 `moon run brief -- audit <蓝图文件>` 核对每个预期，四个案例的退出码依次应为 1、0、0、1。对 AI 素养课运行 `compare` 时，`editor-note` 的未归属分值应从 5 降到 0。

| 蓝图 | 核对事项 | 预期结果 |
| --- | --- | --- |
| AI 素养初稿 | 术语题的 20 分是否达到核验要求，互审是否早于提交 | 两个目标需要复核，编辑说明题还有 5 分未归属 |
| AI 素养改版 | 原文定位任务和互审时序是否补足原有缺口 | 两个目标的缺口补齐，未归属分值归零 |
| 教师研修 | 学员是否先在练习中写替代文本，再为另一张图独立完成考核 | 目标通过 |
| 岗位培训 | 看图识别标识能否充当模拟操作的先行练习 | 考核分值达标，练习要求仍未满足 |

## 参赛者复核待办

1. 选用一份有权使用的课纲与考核方案，移除学生及单位的敏感信息。
2. 自己标注两道题和一个练习，记录每个等级判断对应的原题或评分依据。
3. 运行审计，尝试调整一道题的评分细则或时序，核对结果是否符合预期。
4. 记录复核日期、课程场景、分歧和规则修订。当前样例来自构造数据，尚无真实课程试用记录。

可用 `review-sheet` 导出离线审阅单，在目标旁写下标注依据和拟调整内容。审阅后修改蓝图，再用 `compare` 核对改动效果。
